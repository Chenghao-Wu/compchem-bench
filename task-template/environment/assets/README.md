# Task assets

Everything the agent receives as input goes here and is copied by the
`Dockerfile` into `/workspace/assets/` (the agent's runtime working dir).

Rules:

- **Pin every asset the verifier consumes.** `/workspace/assets` is
  agent-writable, so `tests/verify.py` must never trust the workspace copy of
  any asset it reads. List each such file in `tests/refs.json` under
  `asset_hashes` as `"<rel path>" : "sha256:<64 hex>"`, and re-hash before use.
  (Lint requires: for every `asset_hashes` key, `environment/<rel path>` must
  exist.)
- **Filenames must not confess a fault.** For debugging tasks, a `broken_`
  prefix or a `fixed.inp` deliverable name leaks the planted bug — keep names
  neutral (`no2_geoopt.inp`, not `broken_no2.inp`).
- **Reusable inputs** (potentials, structures, force fields) live in
  `shared/` at the repo root; copy the ones you need into here (see
  `shared/potentials/README.md` and `shared/potentials/qe/SOURCES.md` for
  provenance + hashes).
- For assets generated by running code in-image, commit the generator script
  next to the asset (e.g. `tasks/qe-energy-ranking-audit/environment/generate_assets.sh`,
  `tasks/qe-dihedral-scan-hexane/authoring/`) and record source hashes in a
  `provenance.json`.

Generate a sha256 for pinning with:

```bash
sha256sum environment/assets/<rel-path>
```
