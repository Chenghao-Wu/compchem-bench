【关键设计】
1. Green-Kubo: κ = (1/(3·kB·T²·V))·∫₀^∞⟨J(0)·J(t)⟩dt, kB=1 (LJ单位)
2. 协议: fix ave/correlate 5 200 25000 (Nevery=5, Nrepeat=200 → 窗口5τ,
   Nfreq=25000 → 8个独立块), ave one; 原始热流序列用 fix print 每5步 dump
   (flux_${suffix}.dat) 供 L6 独立重算。
3. 积分截断: 归一化 G(t) 平滑(window=10)找首个过零 → cutoff=round(1.5×(零+10))
4. 六层验证: 存在性/schema → log完整性 → ACF结构 → κ数值容差 → 一致性重算 →
   L6 从原始热流序列独立重算 ACF+κ
5. 生产输入参数化: lmp_serial -log log.T1 -var suffix T1 -in therm.in
   (suffix=T1/T04 分别读 data_T1.lammps/data_T04.lammps)

【实测 κ 值】（修改版 lmp_serial, 1M步平衡资产）
- T=1.0: κ = 1.184269 ± 0.014175
- T=0.4: κ = 2.550080 ± 0.098453
- 低温 κ 更高（贴纸缔合→瞬态网络更刚）→ 物理合理
- 体积 V = 5640.194953916232 (两个温度相同)
- 完整验证器在真实生产数据上 PASS (exit 0)

【发现并修复的问题】（全部已解决）
1. read_data 顺序: 平衡后的 data 文件带 Bond/Angle Coeffs 段, LAMMPS 要求
   样式(bond_style/angle_style/pair_style)在 read_data 前定义; 但系数
   (bond_coeff等)必须在盒子定义(read_data)之后 → therm.in/equilibrate.in 都
   按这个顺序写。
2. 续行符: LAMMPS 用 `&` 不是 `\`。
3. 生成器重叠: 初版 SARW 有 PBC 重叠(镜像距离最小 0.134σ, LJ 能量 9.7e7) →
   重叠检查改用最小镜像距离, 链失败换起点重试 → 最小镜像间距 0.8001。
4. ★角动量修正问题 (重要物理): 原 calc_kappa.in 的
   `fix mom all momentum 100 linear 1 1 1 angular` 在小体系(1200原子)中会持续
   降温(NVE T从0.99掉到0.76)。原因: 净角动量 L~√N, 每次移除的转动动能
   E_rot~L²/I ~ N^(-2/3), 相对总动能 N^(-5/3); 40000原子相对降温比1200原子
   小~340倍。热流修正只需线动量, 已去掉 angular → T 稳住 (T1 平均0.973, T04 平均0.403)。
5. 平衡流程: 先平衡 T=1.0(从线团), 再**淬火** T=0.4(从 data_T1.lammps 出发),
   不能从线团直接平衡 T=0.4(低温贴纸熔体必须从高温平衡态冷却)。
6. cluster_test.sh 的 python 需 numpy: 加了 PYTHON 环境变量覆盖。

【★最关键产出：tarball 构建 bug 已修复并验证】
- 现象: environment/lammps_ex0.tar.gz 原样执行 `make serial` 必失败:
  "No rule to make target '../../lib/netcdf/Makefile.lammps'"。
- 根因: tarball 的 src/Makefile.package 启用了 NETCDF 包
  (PKG_SYSINC = $(netcdf_SYSINC)), Makefile.package.settings 里
  include ../../lib/netcdf/Makefile.lammps, 但 tarball 完全没有 lib/ 目录。
  lammps_Ex0 当初能编过, 是因为它有 lib/netcdf/Makefile.lammps
  (HPC 无 nc-config → netcdf_SYSINC 为空 → dump_netcdf 以存根编译, 与物理无关);
  tarball 打包时漏了 lib/。任务文件(therm.in/verify.py/instruction/solution)
  已确认零 netcdf 依赖。
- 修法: 在干净解压里 `make no-netcdf` 摘掉 NETCDF 包 + rm -rf src/NETCDF,
  再重打包。Makefile.package/.settings 清空, 顶层 dump_netcdf*/netcdf_units*
  删除。二进制能力不变(只是没有 dump netcdf 输出格式, 任务不用)。
- 验证: ①修好的树 `make -j8 serial` 成功(exit 0), lmp_serial -h 可跑;
  ②重打包 tarball(8.8MB, 结构=LICENSE/README/src, 无构建产物, 无 netcdf);
  ③从新 tarball 干净解压再 make serial(等价 Dockerfile 路径) → 构建中
  (final_build.log)。三项全过后 tarball 才算真正修好。
- 顺带: 原 tarball 带过时的 src/lmpinstalledpkgs.h(列着 NETCDF), 已删,
  构建时会重新生成。
